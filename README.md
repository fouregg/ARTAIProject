# ARTAI — мультиязычный генератор изображений с купольным экраном

Экран ввода открыт всем: гость сразу видит, что за сервис. Галерея доступна только
после входа — и кнопка, и сам адрес `/gallery`. Код доступа спрашивается только
в момент отправки запроса — тогда открывается окно с вкладками «Вход» и «Регистрация».
Код даёт 10 генераций. Картинку описывают
одной строкой на одном из семи языков (ru, en, zh, fr, es, pt, ar): бэкенд сам определяет
язык, переводит запрос на английский и отправляет его в `gpt-image-2` через шлюз
[provod.ai](https://provod.ai). Формат всегда 1:1, качество medium — выбирать нечего.
Результат открывается в pop-up окне с четырьмя действиями: сгенерировать снова,
сохранить в галерею, отобразить на экране, закрыть.

«Отобразить на экране» отправляет картинку на **купольный экран** — отдельное устройство,
которое держит открытой страницу `/dome` и собирает из присланных генераций коллаж.

Свежая генерация — черновик: файл живёт на диске **один час**. Отправка на купол или
сохранение в галерею закрепляют картинку навсегда, всё остальное уборщик удаляет.

```
Браузер посетителя            FastAPI + PostgreSQL              Купольное устройство
 React SPA  ──POST /api/generate──►  перевод → gpt-image-2 → png
            ◄──job_id, поллинг───    ↓
 pop-up: [снова][в галерею][на экран] ──► WS /ws/dome ──{id,url}──►  /dome (мозаика)
                                                    ◄── GET /api/images/{id}/file ──
```

## Фирменный стиль

Интерфейс терминала собран по бренд-системе из [`brand_system/`](brand_system/):

| Цвет | HEX | Где используется |
|---|---|---|
| Кремовый | `#F3ECDD` | фон экранов |
| Глубокий синий | `#123B73` | текст, заголовки, активная вкладка |
| Бирюзово-голубой | `#1CB6D4` | обводка активного поля |
| Насыщенный оранжевый | `#E85A1C` | главные кнопки и предупреждения |

Шрифты: **Unbounded** — заголовки, **Tavrida** — текст. Оба переведены в `woff2`
(753 КБ → 252 КБ у Unbounded) и лежат в `frontend/public/fonts/`. В них нет китайских
и арабских глифов, поэтому в `font-family` стоит системный запасной ряд — промпт
на любом из семи языков отрисуется.

Фирменный паттерн — фон всех экранов терминала с прозрачностью 30 %, содержимое лежит
на кремовых карточках, иначе контурные линии мешают читать.

Логотипы: **МФМ 2026** в шапке, **Таврида.Арт** (оператор) и **ПФКИ** (грантодатель)
в подвале. Белая версия знака Тавриды на кремовом фоне не читается — взята чёрная.
Все ассеты подготовлены в `frontend/public/brand/`.

**Купольный экран остаётся чёрным.** Светлый фон на проекции даёт засветку и съедает
контраст коллажа, поэтому бренд-фон применён только к терминалу.

## Стек

- **Бэкенд**: FastAPI, httpx, SQLAlchemy 2.0 (async) + asyncpg, Alembic, PostgreSQL
- **Фронтенд**: React 18 + TypeScript + Vite, без UI-библиотек
- **Изображения**: файлы в `storage/`, метаданные в PostgreSQL

## Быстрый старт

```bash
# 1. Настройки
cp .env.example .env       # и вписать свой PROVOD_API_KEY и DOME_TOKEN

# 2. База данных (порт 5433, чтобы не конфликтовать с локальным PostgreSQL)
docker compose up -d

# 3. Бэкенд
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend && ../.venv/bin/python -m uvicorn app.api.main:get_app --factory --host 0.0.0.0 --port 8000 --workers 1
```

Миграции применяются на старте автоматически (`AUTO_MIGRATE=true`). Вручную:
`cd backend && ../.venv/bin/python -m alembic upgrade head`.

Фронтенд — в отдельном терминале (нужен Node 18+):

```bash
cd frontend
npm install
npm run dev      # дев-сервер на http://localhost:5173 с проксированием /api и /ws
npm run build    # прод-сборка в frontend/dist — её отдаёт сам FastAPI на :8000
```

После `npm run build` всё приложение доступно на `http://localhost:8000` одним origin —
у купола не будет ни CORS, ни mixed-content.

## Структура бэкенда

Приложение собирается фабрикой: `main.py` только вызывает шаги настройки по порядку
и сам ничего не регистрирует.

```
backend/app/
├─ api/
│  ├─ main.py          get_app(): фабрика приложения, запуск через --factory
│  ├─ factories.py     голый FastAPI из настроек
│  ├─ setup.py         setup_logging / setup_middlewares / bind_routes / setup_frontend
│  ├─ lifespan.py      http-клиент шлюза, миграции, фоновые задачи
│  ├─ dependencies.py  Depends: код доступа, анкета, квота, клиент provod
│  └─ routes/          health, auth, legal, generate, gallery, dome
├─ services/           перевод и генерация, доступ, анкеты, уборщик, хаб холста
├─ config.py  db.py  models.py  schemas.py
```

`bind_routes` собирает общий `APIRouter` и подключает его одним вызовом,
`setup_frontend` идёт последним: catch-all маршрут фронтенда иначе перехватил бы `/api`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PROVOD_API_KEY` | Ключ provod.ai. Только на сервере, во фронтенд не попадает |
| `PROVOD_IMAGE_MODEL` | `openai/gpt-image-2` |
| `PROVOD_TEXT_MODEL` | Модель перевода, по умолчанию `google/gemini-3.1-flash-lite` |
| `DATABASE_URL` | `postgresql+asyncpg://artai:artai@localhost:5433/artai` |
| `DOME_TOKEN` | Пароль экрана холста: он же в адресе `/dome?token=…` |
| `ADMIN_TOKEN` | Пароль модерации: адрес `/admin?token=…` |
| `TERMINAL_ID` | Идентификатор киоска, попадает в запись акцепта |
| `STORAGE_DIR` | Каталог с png, по умолчанию `storage/` |
| `CODE_GENERATIONS_LIMIT` | Сколько генераций даёт один код, по умолчанию 10 |
| `IMAGE_TTL_MINUTES` | Сколько живёт незакреплённая картинка, по умолчанию 60 |
| `CLEANUP_INTERVAL_MINUTES` | Как часто работает уборщик, по умолчанию 10 |
| `CORS_ORIGINS` | Список через запятую, нужен только для дев-сервера Vite |

> **Важно про идентификаторы моделей provod.ai.** В каталоге `/v1/models` поле
> `canonical_slug` содержит дату (`google/gemini-3.1-flash-lite-20260507`), но
> chat-эндпоинт такой идентификатор **не принимает** — нужен `google/gemini-3.1-flash-lite`.
> Для картинок, наоборот, работает полный слаг `openai/gpt-image-2`.

## Как подключается цифровой холст

Экран холста **не нужно** делать доступным извне: публичный IP, проброс портов и VPN
не требуются. Устройство само открывает исходящее соединение к серверу — сначала обычный
HTTP за страницей, потом WebSocket за обновлениями. За NAT это работает так же, как любой
сайт. Публичный адрес нужен только серверу.

Если сеть площадки режет апгрейд до WebSocket (бывает на строгих прокси), экран не
останется пустым: он раз в 10 секунд забирает снапшот коллажа обычным GET-запросом
и честно пишет об этом в углу. Как только сокет удастся поднять, опрос прекращается.

При работе через туннель наружу сервер пускается так:

Боевой адрес — **https://ai.tavrida.art**. Для временного показа с ноутбука
годится туннель:

```bash
cloudflared tunnel --url http://localhost:8000
```

На устройстве купола открыть в киоск-режиме:

```
https://<выданный-домен>/dome?token=<DOME_TOKEN>
```

Страница сама переключается на `wss://`, переподключается с нарастающей задержкой
и после разрыва заново забирает снапшот коллажа — экран рассчитан на работу сутками.
Очистить купол: `DELETE /api/dome/items?token=<DOME_TOKEN>`.

Хаб подключений живёт в памяти процесса, поэтому uvicorn запускается **в один воркер**.
Для нескольких воркеров понадобится вынести рассылку в Redis pub/sub.

## Учётки

Учётка — это адрес электронной почты. Пароля нет и письма не отправляются: почта
одновременно и логин, и единственный признак участника, ровно как раньше был код.
Она даёт `CODE_GENERATIONS_LIMIT` генераций суммарно, без суточного сброса;
неудачные попытки не считаются.

Регистрация заводит учётку сама — отдельного шага «создать аккаунт» нет. Если гость
вводит на вкладке «Вход» незнакомую почту, окно молча переключается на «Регистрацию»
и подставляет её: незнакомый адрес — не ошибка, а признак того, что человек здесь впервые.

Адрес приводится к нижнему регистру и обрезается по краям, поэтому `Ivan@Example.COM`
и `ivan@example.com` — одна и та же учётка.

Как это работает в запросах: фронт кладёт почту в `localStorage` и шлёт заголовком
`X-Access-Email` в каждом запросе. Генерация, сохранение в галерею и отправка на холст
требуют зарегистрированной почты; страница холста `/dome` — нет, у неё свой `DOME_TOKEN`.

> **Про безопасность.** Пароля нет, поэтому чужой квотой может воспользоваться любой,
> кто знает адрес. Вход ограничен по частоте — 10 попыток с одного адреса в минуту
> (`LoginRateLimiter` в [`backend/app/services/access.py`](backend/app/services/access.py)).
> Для установки в зале этого достаточно. Для открытого интернета нужен вход по коду
> из письма — тогда понадобится SMTP.

> **Про персональные данные.** Согласие перечисляет закрытый список обрабатываемых
> данных: фамилия, имя, отчество, дата рождения, страна, текст запроса и идентификатор
> изображения. **Почты в этом списке нет** — тексты соглашения (п. 9.1) и согласия
> нужно дополнить, иначе её сбор согласием не покрыт.

## Модерация запросов

Пункт 3.1 Соглашения описывает порядок: перечень запрещённых слов → перевод →
автоматическая модерация → генерация. Проверка идёт **до** перевода и генерации,
по исходному тексту на любом языке, и состоит из двух ступеней:

1. **Стоп-лист** — [`backend/app/moderation/stopwords.txt`](backend/app/moderation/stopwords.txt),
   один корень на строку, сравнение по вхождению. Мгновенно, без сети, ловит явную брань.
2. **Классификатор** на текстовой модели — отдельный вызов со своей подсказкой,
   не совмещённый с переводом: попытка сбить модель указаниями внутри запроса
   повлияет только на один из двух вызовов.

Категории заданы в [`services/moderation.py`](backend/app/services/moderation.py):
`adult`, `profanity`, `gore`, `war`, `racism`, `children`, `disaster`, `ua_svo`,
`scatology`, `substances`. Формулировки там — часть настройки: правя описание категории,
вы меняете поведение модерации.

В стоп-листе строка вида `[код]` переключает категорию для идущих ниже слов,
поэтому «навоз» помечается как `scatology`, а не как брань.

Отказ гостю выглядит одинаково для всех причин — «Запрос не может быть обработан.
Попробуйте сформулировать его иначе.» (п. 3.4: основание не раскрывается). Сработавшие
категории пишутся в `generations.moderation_categories`, чтобы оператор мог ответить
на возражение по п. 8.1.

| Настройка | Значение |
|---|---|
| `MODERATION_ENABLED` | Выключает проверку целиком |
| `MODERATION_MODEL` | Модель классификатора; пусто — берётся модель перевода |
| `MODERATION_FAIL_OPEN` | Классификатор недоступен: `false` — отклонять (по умолчанию), `true` — пропускать |

## Коллаж: превью и страницы

Оригинал весит около двух мегабайт, а плитка на холсте занимает сотню пикселей.
Поэтому рядом с картинкой сохраняется превью 384 px в WebP (~33 КБ, в 55 раз легче)
и отдаётся по `/api/images/{id}/thumb`. Коллаж, галерея и админка берут превью,
оригинал открывается только в pop-up окне. Для картинок, сделанных до появления
превью, оно создаётся при первом обращении.

К концу фестиваля изображений будут тысячи, одним полотном их не показать: плитка
выродится в точку, а браузер задохнётся. Холст листает страницы **по 50 изображений**,
меняя их **раз в минуту**, и подписывает внизу «Страница N из M». Страница из 50 плиток
весит около 0,2 МБ вместо 90 МБ на оригиналах.

## Модерация холста

Страница `/admin?token=<ADMIN_TOKEN>` показывает всё, что отправляли на холст, и позволяет
снять отдельную плитку. Токен свой, отдельный от `DOME_TOKEN`: экран умеет только показывать,
модерация — только под админским.

Снятие **мягкое**: гасится флаг `is_visible`, запись в `dome_items` остаётся, плитку можно
вернуть кнопкой. Это отвечает п. 7.1 Соглашения (оператор вправе прекратить показ) и
п. 8.3 (прекратить в течение суток по обращению), при этом сохраняется след того,
что и когда показывалось. Экран холста реагирует мгновенно: по сокету уходит событие
`image_removed`, а если сокет заблокирован — плитка исчезнет на ближайшем опросе.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/dome` | Все плитки, включая скрытые |
| DELETE | `/api/admin/dome/{id}` | Снять с холста |
| POST | `/api/admin/dome/{id}/restore` | Вернуть на холст |
| DELETE | `/api/admin/dome` | Очистить холст целиком |

## Срок хранения изображений

Файл удаляется, если генерации больше часа и она **не закреплена**:

- закрепляет отправка на купол (`POST /api/dome/display`);
- закрепляет сохранение в галерею (`POST /api/gallery`).

Уборщик ([`backend/app/services/cleanup.py`](backend/app/services/cleanup.py)) просыпается
каждые 10 минут, а также делает проход сразу на старте — чтобы догнать простой сервера.
Запись в `generations` при этом **не удаляется**: это журнал, по нему считаются суточные
квоты. У просроченной записи обнуляется `file_path`, а статус становится `expired`, и
`/api/images/{id}/file` отвечает `410 Gone` с понятным текстом вместо безликого 404.

Удаление из галереи не удаляет файл сразу: если картинка ещё висит на куполе, она остаётся,
а иначе её подберёт ближайший проход уборщика.

В pop-up окне до нажатия «сохранить»/«на экран» показывается точное время удаления —
бэкенд отдаёт `expires_at` вместе с генерацией.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/login` | Вход по коду, возвращает лимит, остаток и признак `registered` |
| GET | `/api/auth/me` | Состояние кода из заголовка `X-Access-Code` |
| POST | `/api/auth/register` | Анкета участника и акцепт обоих документов |
| GET | `/api/legal` | Тексты соглашений, экранные надписи, ссылка на политику |
| GET | `/api/legal/policy.pdf` | Политика обработки персональных данных |
| POST | `/api/generate` | Запускает генерацию, возвращает `job_id`; `401` без кода, `429` при исчерпании |
| GET | `/api/jobs/{job_id}` | Статус: `queued / translating / generating / done / error` |
| GET | `/api/images/{id}/file` | Отдаёт png; `410`, если срок хранения истёк |
| POST/GET | `/api/gallery` | Сохранить / список |
| DELETE | `/api/gallery/{id}` | Удалить из галереи (файл остаётся) |
| POST | `/api/dome/display` | Добавить плитку в коллаж и разослать по WS |
| GET/DELETE | `/api/dome/items` | Снапшот / очистка (нужен `?token=`) |
| WS | `/ws/dome?token=…` | События `snapshot`, `image_added`, `cleared`, `ping` |
| GET | `/api/health` | БД, доступность модели, число подключённых экранов |

Генерация занимает 30–90 секунд, а туннели рвут HTTP-запрос примерно на 100 с — поэтому
`/api/generate` сразу возвращает `job_id`, а фронт опрашивает `/api/jobs/{id}` раз в секунду.

## Ограничения gpt-image-2 на этом шлюзе

- `response_format` — только `b64_json`, ссылки на картинку не бывает, файл сохраняет бэкенд;
- `n = 1` за запрос;
- размер кратен 16, от 655 360 до 8 294 400 пикселей; используются пресеты
  `1:1 → 1024x1024`, `3:2 → 1536x1024`, `2:3 → 1024x1536`;
- `quality`: `auto | low | medium | high`, `output_format`: `png | jpeg | webp`;
- модель поддерживает стриминг с `partial_images` — сейчас не используется.

## Что дальше

- В Соглашении (п. 3.1) описана проверка промпта по перечню запрещённых слов **до** перевода.
  Сейчас её нет: работает только модерация на стороне модели. Перечень слов не передавался —
  как только он появится, проверку можно поставить первым шагом в `run_generation_job`.
- В текстах соглашения и согласия оставлены пропуски для адреса электронной почты
  (п. 8.1 Соглашения и срок отзыва согласия) — их нужно заполнить в
  [`backend/app/legal/`](backend/app/legal/) до запуска. После правки текста поменяйте
  версию в `backend/app/services/legal.py`: хеш пересчитается автоматически.
- Галерея сейчас общая: гость видит все сохранённые картинки, а не только свои.
  Чтобы сделать её персональной, достаточно отфильтровать список по `user_id`
  в [`backend/app/api/routes/gallery.py`](backend/app/api/routes/gallery.py).
- Интерфейс переведён на семь языков, но переключатель убран, поэтому показывается
  русский. Вернуть выбор — восстановить селектор языка на странице ввода.
